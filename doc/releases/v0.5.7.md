# ClipMenu 0.5.7

This patch commits edited integer preference fields—such as `Max clipboard history size:`—only after editing finishes instead of on every keystroke. It supports **macOS 12 or later** on **Intel and Apple silicon** Macs. **ClipMenu 0.5.0–0.5.6 users can update through Sparkle normally.**

## Changes

- Typing into **`Max clipboard history size:`** (and other integer stepper fields in Preferences) now keeps edits in a local draft and commits on **Return**, focus loss, Preferences window close, or app termination, so typing intermediate digits such as **`1`** on the way to **`1000`** no longer trims existing clipboard history.
- Stepper arrows continue to apply changes immediately, invalid or overflowing input preserves the current setting instead of falling back to the minimum, and unedited drafts never overwrite values updated elsewhere.

## Validation

The Debug build and all **114 unit tests** passed, including integer preference draft parsing, clamping, and commit-timing checks.

## 日本語

「記憶する履歴の数:」などの数値設定フィールドで、キー入力ごとではなく編集完了時に値を反映するよう修正したパッチリリースです。**macOS 12 以降の Intel Mac と Apple シリコン搭載 Mac** に対応します。**ClipMenu 0.5.0〜0.5.6 からは Sparkle で通常どおり更新できます。**

- 環境設定の **「記憶する履歴の数:」**（および他の整数ステッパー入力欄）への入力を一時的な下書きとして保持し、**Return** キー押下・フォーカス移動・環境設定ウインドウを閉じるとき・アプリ終了時に確定するようになりました。これにより **`1000`** と入力する途中の **`1`** が即座に適用されて既存のクリップボード履歴が切り詰められる問題を防ぎます。
- ステッパーの上下矢印は引き続き即座に反映され、不正な文字列や桁溢れの入力があった場合は最小値へ戻さず現在の設定値を維持します。また、未編集の入力欄が他所で更新された値を上書きすることもありません。

Debug ビルドおよび全 **114 件のユニットテスト**（整数設定フィールドの下書きパース・範囲制限・確定タイミングのテストを含む）がすべて成功しました。
