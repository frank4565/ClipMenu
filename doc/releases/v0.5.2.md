# ClipMenu 0.5.2

This patch fixes Command-number menu selection and delayed automatic paste. It supports **macOS 12 or later** on **Intel and Apple silicon** Macs.

**ClipMenu 0.5.0 and 0.5.1 users can update through Sparkle normally.** When upgrading from an older Objective-C version, quit ClipMenu and install this release manually; the original updater uses a different feed and trust key.

The app continues to use a local **ad-hoc code signature**, without Apple Developer ID signing or notarization. Published update ZIPs use separate Sparkle Ed25519 signatures.

## Changes

- Command-number shortcuts select the corresponding menu item and close the menu. With automatic paste enabled and Accessibility permission granted, the selected item pastes into the destination without requiring another keyboard event.
- Selecting an existing history item no longer captures that same clipboard write again, avoiding redundant history saves and menu rebuilds. Later external copies, snippets, and action results remain eligible for normal history capture.
- History encoding and writes run in the background, and clipboard polling and menu rebuilding wait for an active paste to finish. Existing clip identifiers and saved-history formats are preserved; final saving at quit is ordered after pending writes.

## Validation

The unit suite passed **111 tests with no failures**. The user confirmed the beta 4 fix on the affected **MacBook Air running macOS 27.0.1**, selecting with **Command–1 and automatically pasting into Safari's address bar**.

## 日本語

メニューの Command と数字キーによる選択、および自動ペーストの遅延を修正したパッチリリースです。**macOS 12 以降の Intel Mac と Apple シリコン搭載 Mac** に対応します。

**ClipMenu 0.5.0 と 0.5.1 からは Sparkle で通常どおり更新できます。** 以前の Objective-C 版から更新する場合は、ClipMenu を終了して、このリリースを手動でインストールしてください。従来のアップデータとは更新フィードと検証キーが異なります。

アプリは引き続きローカルの**アドホック署名**を使用し、Apple Developer ID による署名や公証は行いません。公開する更新 ZIP は、別途 Sparkle の Ed25519 署名で検証します。

- Command と数字キーで対応するメニュー項目を選択し、メニューを閉じるようにしました。自動ペーストが有効でアクセシビリティ権限が許可されている場合、追加のキー操作を待たずに選択した項目をペーストします。
- 既存の履歴項目を選択した際に、そのクリップボードへの書き込みを再度記録しないようにし、不要な履歴保存とメニューの再構築を防ぎました。その後の外部アプリからのコピー、スニペット、アクションの結果は通常どおり履歴に記録されます。
- 履歴のエンコードと書き込みをバックグラウンドで行い、ペースト中のクリップボード監視とメニュー再構築を完了まで延期します。既存の履歴 ID と保存形式を維持し、終了時の最終保存は保留中の書き込みの後に実行します。

### 検証

ユニットテストは **111 件すべて成功し、失敗はありませんでした**。問題が発生していた **macOS 27.0.1 の MacBook Air** で、**Command–1 による選択と Safari のアドレスバーへの自動ペースト**が動作することを、ユーザーが beta 4 で確認しました。
