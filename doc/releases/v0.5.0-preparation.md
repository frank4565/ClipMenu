# ClipMenu 0.5.0 release preparation

The first formal release of the Swift port uses tag `v0.5.0`, marketing version
`0.5.0`, and bundle build `6.0.99`. It supports macOS 12 or later on Apple silicon
and Intel Macs. The tag is reserved for the reviewed commit after the Swift branch
is merged into `master`; no release tag has been created during preparation.

## Review material

- The README describes the Swift app, supported features, permissions, migration,
  and current build/test commands. Four fresh native screenshots show General,
  Menu, Action, and the Snippet Editor. They were captured from the current Debug
  app in an isolated support directory and defaults domain with synthetic data.
- Curated English and Japanese Sparkle notes are in `v0.5.0.en.html` and
  `v0.5.0.ja.html`. `v0.5.0.md` supplies the GitHub release body.
- Release ZIPs contain the ClipMenu and resolved Sparkle license notices beside
  the app. The delivery extraction verifies their exact bytes; the signed app
  bundle is copied without adding or changing its resources.
- A local unsigned release preview validates stable version `6.0.99`, universal
  app architecture, ZIP delivery, license notices, and the preview appcast. It is
  an inspection artifact, not the production release or an automatic update.

## Repository readiness

The Swift history includes `master` and can merge without conflicts. The Validate
workflow runs unit tests, release-helper tests, and a universal unsigned Release
preview. The Release workflow must reach `master` before GitHub will allow its
manual dispatch. Pages already uses Actions and permits the `v*` version tags.
The stable tag and formal release do not already exist.

The latest validation before this documentation update passed at commit
`96c8dd0edb9573a2b88de972a462745823c4da13`:
[Validate run 38127470690](https://github.com/frank4565/ClipMenu/actions/runs/38127470690).
The new pull request supplies validation for the final preparation commit.

## Required signing configuration

The repository already has the Sparkle private-key secret and the public update
key/feed variables. Formal publication is waiting for this Apple configuration:

| Kind | Required name |
| --- | --- |
| Repository variable | `APPLE_TEAM_ID` |
| Repository secret | `DEVELOPER_ID_CERTIFICATE_P12_BASE64` |
| Repository secret | `DEVELOPER_ID_CERTIFICATE_PASSWORD` |
| Repository secret | `APPLE_NOTARY_KEY_P8_BASE64` |
| Repository secret | `APPLE_NOTARY_KEY_ID` |
| Repository secret | `APPLE_NOTARY_ISSUER_ID` |

Configure these through GitHub's repository settings as described in
[the release guide](../releasing.md). Keep private certificate/key material out of
Git, release assets, screenshots, and chat messages. The audit checked configured
names only and did not read private values.

## Final sequence

1. Review the preparation pull request and require its Validate run to pass.
2. Merge `swiftui-native` into `master`, preserving the Swift and Sparkle history.
3. Complete the Apple configuration above. Run the Release workflow with
   `version_tag=v0.5.0` and `dry_run=true` if another hosted preview is desired.
4. Create the annotated `v0.5.0` tag at the reviewed `master` commit and push it.
   The tag starts the production signing, notarization, GitHub Release, and Pages
   publication pipeline.
5. Verify the downloaded public ZIP checksum, Developer ID signature and stapled
   ticket, and the deployed stable appcast item. Test manual installation and
   permissions on the target MacBook Air.

Existing Objective-C ClipMenu installations need this first Swift version
installed manually because the old updater uses a different feed and trust key.
