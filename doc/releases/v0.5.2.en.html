ClipMenu 0.5.2

This patch fixes Command-number menu selection and delayed automatic paste. It supports Intel and Apple silicon Macs running macOS 12 or later.

Updating

ClipMenu 0.5.0 and 0.5.1 users can update through Sparkle normally. When upgrading from an older Objective-C version, quit ClipMenu and install this release manually; the original updater uses a different feed and trust key.

The app continues to use a local ad-hoc code signature, without Apple Developer ID signing or notarization. Published update ZIPs use separate Sparkle Ed25519 signatures.

What changed

  • Menu shortcuts and paste: Command-number shortcuts select the corresponding item and close the menu. With automatic paste enabled and Accessibility permission granted, the selected item pastes into the destination without requiring another keyboard event.
  • History capture: selecting an existing history item no longer captures that same clipboard write again, avoiding redundant history saves and menu rebuilds. Later external copies, snippets, and action results remain eligible for normal history capture.
  • Background work: history encoding and writes run in the background, and clipboard polling and menu rebuilding wait for an active paste to finish. Existing clip identifiers and saved-history formats are preserved; final saving at quit is ordered after pending writes.

Validation

The unit suite passed 111 tests with no failures. The user confirmed the beta 4 fix on the affected MacBook Air running macOS 27.0.1, selecting with Command–1 and automatically pasting into Safari's address bar.
